# 长任务自动交接：调研与开发设计

日期：2026-09-17。工作名：Agent Relay（暂定）。状态：设计提案，未实现、未安装、未启动自动续跑。

## 结论

目标是让同一项长期工作穿过多个新会话，始终围绕用户真实需求推进，并在可恢复的进度节点交接。单独一份 `SKILL.md` 能描述流程，但不能保证事件触发、进程存活、新会话创建和交接事务完成。建议采用 **共享 skill + 持久化交接协议 + 客户端适配器 + 会话外控制器**；控制器优先复用现有工具，先验证再决定是否自研。

最值得先评估的是 [Ralph Orchestrator](https://github.com/mikeyobrien/ralph-orchestrator)，已有 Claude Code、Codex 等后端、循环、任务和记忆机制。若可以接受改用统一工作入口，再评估 [GSD Pi](https://github.com/open-gsd/gsd-pi)，其自动模式按工作单元使用新会话。DSH 本身已有 [Ralph 工具](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/workflow/tool-ralph/README.md)，可借用其能力，但新子 agent 不等于用户要求的原生新对话。

在本次核实范围内，尚未确认一个现成工具同时满足“三客户端、保持有效模型、自动识别交接节点、保留用户原话和变更、原界面可见新对话、可靠自动续跑”的完整组合。这是有边界的调研结论，并非断言不存在。

## 最重要的设计选择

1. 用户原话和后续修正独立保存；新会话不能只读取上一份摘要。
2. 先记录交接意图，完成当前可验收的工作单元，确认没有仍在修改项目的旧任务，再交接。
3. 新会话先读取材料并返回接手确认，控制器随后才允许它修改项目。
4. 模型、提供商、推理设置、工作目录、权限与工具配置都属于交接内容；模型不匹配时不能悄悄替换。
5. 每次交接自动重复，无需用户盯着完成时间；用户暂停、真正的外部阻塞和总预算边界可以终止自动链。
6. “新上下文”“新会话”“原生界面可见新对话”“新操作系统窗口”分开验收，不互相冒充。
